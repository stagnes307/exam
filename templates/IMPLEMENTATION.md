# 구현 이해·인지 대비 설명을 작성하는 AI 참고 양식

쉬운 설명은 구현 때부터 `PROGRESS.md`에 남기고 5단계에서 최신 코드와 다시 대조한다. 별도 구현 설명 문서를 기본 산출물로 만들지 않는다. 지정 실행·협업·설명 문서가 있으면 필요한 근거를 그 문서에도 반영하되, 사용자가 읽을 안내는 `PROGRESS.md`에 모은다. 전체 구현·사용자 테스트 완료를 전제로 하지 않는다.

## 기준과 기록 위치

- 기준 코드 판본·입력/조건·현재 Phase·설명 제공 시점.
- PRD의 관련 요구, PLAN의 관련 질문/확정 해석, 담당 Phase의 구현·검증 근거 링크.
- 사용자 확인/미확인·구현/미구현·실패·보장하지 못하는 범위.

기술 책임표·실행 명령/디렉터리·종료 코드·측정 결과는 담당 Phase 상세에 남긴다. `PROGRESS.md`에는 핵심 결과와 근거 링크를 적고 기술 로그를 그대로 복사하지 않는다.

## PROGRESS에 남길 Phase별 이해 노트

구현한 핵심 기능마다 아래 내용을 짧은 항목과 입력 한 건의 예시로 설명한다. 기술 용어에는 쉬운 뜻을 붙이고 소스 전체를 붙이지 않는다.

1. **처리 흐름과 책임:** 사용자의 입력·시작 상태부터 진입점→검사→계산→저장/결과까지 실제 파일·함수를 연결한다. 누가 직접 검사하고 다른 계층에 무엇을 맡기는지 설명한다.
2. **선택 이유와 손실:** 채택한 방법과 대안, 선택 이유·품질·비용·규모/조건 변경의 손실을 실제 근거로 설명한다. 계획만 있는 선택은 확정 구현과 구분한다.
3. **실패와 복구:** 입력 오류·계산/검증 실패·저장 실패·중단·재시작 때 진행 중 작업·임시/최종 결과 중 무엇이 남고, 누가 확정/복구하는지 설명한다.
4. **검증 근거와 한계:** 실제 확인한 범위, 손계산/독립 검사, 고의 오류 거절, 다른 유효 결과 수용과 미확인을 설명한다. 공유 파서·시간 함수가 함께 틀릴 수 있는 사례와 단일 건/하루를 전체 기간/공유 자원 검증으로 볼 수 없는 이유도 해당 범위에서 짚는다.

자료·조건과 결과의 관계, 저장·조회·내보내기의 일치는 실제 구현 구간만 설명한다. Worker·큐·별도 프로세스가 없으면 없다고 설명하며, 요구에 없는 구조를 설명을 채우려고 만들지 않는다. 사용자가 더 읽고 싶을 때 열 수 있도록 실제 코드와 해당 Phase의 근거로 연결한다.

## 최신 상태와 이해 확인

- 코드·자료·조건이 달라지면 영향받은 이해 노트를 갱신하고 사용자 재확인 필요 범위를 표시한다. 과거 설명을 최신 구현의 사실로 재사용하지 않는다.
- 이해하기 어려운 부분의 재설명도 `PROGRESS.md`에서 갱신하고 다른 단계로 자동 전환하지 않는다.
- 설명 제공과 사용자 이해는 별개다. 실제 보고 없이 이해 완료·직접 검증·제출 완료로 표시하거나 퀴즈를 자동 생성하지 않는다.
- 다음 `PROMPTS.md`의 절을 안내하고 필요한 작업별 차이는 그 기본 프롬프트 아래에 보충한다. 별도의 추천 프롬프트를 다시 작성하지 않는다.

인지 대비는 AI 사용이 허용된 개발 중에 현재 구현의 책임·근거·한계를 이해하도록 돕는 기록이다. 실제 AI 금지 단계의 답변 작성·첨삭을 수행하거나 평가 점수·사용자의 이해를 보장한다고 쓰지 않는다.
