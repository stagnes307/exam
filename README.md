# 시험 개발 하네스

시험 과제를 파악하고 Phase 단위로 구현·검증한 뒤 직접 테스트하고 제출하는 지침·추천 프롬프트·양식이다.

**1 문제 파악 → 2 PRD·계획 확인 → 3 Phase 구현·AI 검증 → 4 직접 테스트 → 5 구현 설명 확인 → 6 제출 점검**

3→4는 Phase별로 반복한다. 한 Phase 안의 여러 기능과 수정·재검증은 이어가고 기능마다 사용자 확인을 받지 않는다. Phase가 끝나면 짧은 설명과 직접 테스트 안내를 함께 제공하고 사용자의 다음 요청을 기다린다.

## 시작

[실제 시험용 빠른 사용 가이드](QUICKSTART.md)에 가져오는 명령과 Phase별 짧은 복사 요청을 모았다. 실제 시험 프로젝트를 작업 루트로 사용하고 하네스는 허용된 새 폴더에 가져온다.

```sh
git clone --depth 1 --filter=blob:none --sparse https://github.com/stagnes307/ai-assessment-practice.git exam-harness
```

복제가 성공한 뒤 다음 명령을 실행한다. 실패하면 주소·접근 권한을 확인하거나 시험에서 허용된 제공 사본의 실제 폴더를 사용한다.

```sh
git -C exam-harness sparse-checkout set --no-cone "/exam-kit/"
```

이 저장소에서 하네스의 실제 경로는 **`exam-harness/exam-kit/`**이다. 다른 레포로 옮겨 쓰면 URL과 실제 폴더 위치를 맞춘다. 실제 프로젝트에서 Codex를 시작한 뒤 [빠른 시작](QUICKSTART.md#1-문제-파악) 또는 [START.md](START.md)의 경로를 바꿔 전달한다. 첫 요청은 문제 파악까지만 수행하며, PRD·Phase 계획 확정과 구현은 다음 요청으로 진행한다. 하위 폴더 지침이 상위 프로젝트에 자동 적용된다고 가정하지 않는다. 실제 루트·지침 경로/범위·`AGENTS.override.md`를 확인하고 자동 탐색과 명시적 읽기를 구분한다. 기존 지침·원문은 보존한다. [공식 지침 탐색 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 내가 할 일과 추천 프롬프트

| 단계 | AI가 할 일 | 내가 확인할 것 | 추천 요청 |
| --- | --- | --- | --- |
| 1 문제 파악 | 원문·자료 관계·대표 입력과 업무 질문 정리 | 실제 목적·필수 요구·모호한 기준. 담당자에게 질문하고 답변 전달 | [시작](START.md), [1단계](PROMPTS.md#1-문제-파악) |
| 2 PRD·계획 | 요구·제외 범위·완료 기준과 Phase별 구현/검증 순서 작성 | 만들 범위·우선순위·각 Phase의 결과 | [2단계](PROMPTS.md#2-prd와-계획-확인) |
| 3 Phase 구현·AI 검증 | 승인한 Phase의 여러 기능을 구현·검증하고 짧게 설명. 직접 테스트 안내도 함께 제공 | 실제 동작·실패 후 상태·확인 근거·남은 통합 검증 | [3단계](PROMPTS.md#3-phase-구현과-ai-검증) |
| 4 직접 테스트 | 사용자 보고를 기록하고 요청된 실패 수정·재검증 | 안내된 조작을 직접 수행하고 판본·정상/실패/미확인 전달 | [4단계](PROMPTS.md#4-직접-테스트와-수정) |
| 5 구현 설명 | 실제 입력·파일·함수·책임·실패 처리·품질 비교를 설명 | 처리 흐름·선택 이유·한계와 이해가 어려운 부분 | [5단계](PROMPTS.md#5-구현-설명-확인) |
| 6 제출 점검 | 필수 파일·실행법·실제 출력·문서 일치 확인 | 제출 대상·남은 문제·실제 제출 조작 | [6단계](PROMPTS.md#6-제출-점검), [점검표](FINISH.md) |

Phase는 연결된 여러 기능을 묶되 실행 가능한 결과·완료 기준·검증을 갖추게 나눈다. 단계/Phase가 끝나면 사용자가 다음 범위를 요청한다. 침묵·AI 자체 검증을 사용자 확인으로 간주하지 않는다. 사용자 확인이 일부뿐이면 그 범위만 기록한다.

중간에 종료해야 하면 **[중간 종료 요청](PROMPTS.md#예외-중간-종료와-제출-정리)**을 쓴다. 테스트·설명 완료를 전제로 삼지 않고 현재까지의 구현·검증·짧은 설명·필수 제출물·미확인을 정리한다. 실제 시험의 중단 지시와 AI 사용 범위가 우선한다. 세션이 바뀌면 **[재개 요청](PROMPTS.md#예외-세션-재개)**으로 현재 단계·승인된 Phase를 확인한다.

## 복기에서 반영한 확인 기준

- 기능별 짧은 설명을 구현 때부터 남겨 중간 종료에도 실제 흐름·실패 상태·확인 근거를 볼 수 있게 한다.
- 데이터 변경은 정상 A → 오류 B 거절 → 정상 C 적용 → 재계산·저장·조회·내보내기의 판본/조건/내용을 연결해 확인한다. 각 자료 종류의 변경과 중단·재시작도 과제에 맞춰 대조한다.
- 규칙 준수와 품질을 나누고 같은 입력에서 기준 방법·현재 방법의 품질 지표와 실행 비용을 비교한다. 규모·조건 변경, 손실·미실행도 공개한다.
- 직접 검사/다른 계층 위임/미구현 규칙과 진행 중/임시/최종 상태의 담당 위치·확정 시점·실패 결과를 실제 코드로 기록한다.
- AI 검증·사용자 직접 확인·설명 제공·사용자 이해·실제 제출은 서로 다른 상태다. 사용자 판단과 수행 결과를 지어내지 않는다.

실제 과제의 요구·양식·허용 도구가 우선이다. 제공 원문·원본 자료를 보존하고 변경 테스트는 복사본으로 한다. 하네스 폴더의 빈 양식은 보존하며 시험 자료·완성 답안·채운 기록·비밀값을 범용 레포에 섞지 않는다. AI 금지 단계에서는 이 하네스를 이용한 답변 작성·첨삭도 요청하지 않는다.

이 폴더 전체와 `templates/`를 GitHub 레포에 올려 사용한다. 별도 설치·자동 초기화·ZIP 생성은 필요하지 않다. 실제 플랫폼 실행·시험 성과를 보장하는 프로그램은 아니다.
