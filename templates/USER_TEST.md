# 직접 테스트 안내를 작성하는 AI 참고 양식

별도 사용자 테스트 문서를 기본 산출물로 만들지 않는다. 사용자가 읽을 조작 방법과 실제 보고는 `PROGRESS.md`에 모으고, AI 검증·수정·재검증 근거는 해당 Phase 상세 파일에 기록한다. 과제가 별도 양식/기존 테스트 문서를 지정하면 그 문서를 유지하고 실제 경로로 연결한다.

## Phase 종료 시 PROGRESS에 안내할 내용

- Phase·관련 기능·실제 테스트 판본(커밋 또는 변경 상태의 식별 근거).
- 실행 명령·작업 디렉터리·실제 UI 주소/포트·유지할 프로세스. CLI만 있으면 CLI 명령을 안내하고 없는 URL을 만들지 않는다.
- 시작 화면/역할·준비 자료·초기 적용 데이터/조건·기존 결과 상태.
- 정상 흐름과 중요한 오류·실패 후 상태를 확인할 입력·조작 순서·기대 결과.

| 테스트 항목 | 시작 상태·입력 | 직접 할 조작 | 기대 결과 | 사용자 보고·확인 주체/판본 | 상태 |
| --- | --- | --- | --- | --- | --- |
| | | | | | 미확인 |

이 표의 실제 작성 위치는 `PROGRESS.md`다. 보고 전의 사용자 결과는 빈칸/미확인으로 둔다. AI가 기대하는 결과를 사용자의 수행 결과로 미리 채우지 않는다. 관련 요구·검증 ID와 기술 근거는 해당 Phase에 연결해 사용자가 기술 표 전체를 읽어야 테스트할 수 있게 만들지 않는다.

데이터 변경은 원본 복사본으로 한다. 데이터 적용·재계산·저장·내보내기가 있으면 담당 Phase의 일관성 검증을 직접 조작할 절차로 바꾼다. 화면 표시와 실제 저장·조회·출력의 데이터 판본·조건·내용을 함께 확인한다. 아직 없는 기능은 후속 통합 검증으로 남긴다.

## 보고를 받은 뒤 처리

1. 보고된 주체·판본·정상/실패/미확인·생략 범위만 `PROGRESS.md`에 기록한다. 일부 확인을 전체 통과로 확대하지 않는다.
2. 실패의 시작 상태·입력·조작·기대·실제를 확인하고, 승인된 범위에서 수정·AI 재검증을 수행해 해당 Phase에 근거를 기록한다.
3. 코드·자료·조건 변경의 영향 항목을 재확인 필요로 표시하고 이전 보고는 판본과 함께 보존한다. `PROGRESS.md`에는 다시 해볼 조작을 안내한다.
4. Phase 상태를 전체 `PLAN.md` 목차에 반영하고 다음 `PROMPTS.md` 단계/절과 기본 문구만 복사할지 보충도 포함할지 안내한다. 새 프롬프트를 반복 생성하지 않는다.

Phase마다 사용자의 다음 요청을 기다린다. 중간 종료를 위해 테스트 완료를 요구하거나 확인 결과를 만들어내지 않는다. AI 대리 확인을 사람의 직접 확인으로 바꾸지 않는다.
