# 필요한 사용자 직접 확인을 안내하는 AI 참고 양식

CLI 명령 실행·입력 검증·자동 회귀 검사는 3단계에서 AI가 실제로 실행하고 수정·재검증한다. 이미 통과한 같은 명령을 사용자에게 다시 실행하게 하거나, CLI만 구현된 Phase마다 4번 요청·사용자 보고란을 필수로 요구하지 않는다. AI 실행 근거는 해당 Phase 상세 파일에, 사용자가 읽을 결과·한계·쉬운 설명은 `PROGRESS.md`에 기록한다.

별도 사용자 테스트 문서를 기본 산출물로 만들지 않는다. 과제가 별도 양식/기존 테스트 문서를 지정하면 그 문서를 유지하고 실제 경로로 연결한다. 필수 검사 중 실행하지 못한 항목은 원인·범위·영향을 미확인으로 남기고 완료로 바꾸지 않는다. 실행 환경 문제도 AI가 해결 가능한 범위를 먼저 처리하며, 같은 검사를 사용자에게 자동으로 전가하지 않는다.

## 사용자 직접 확인이 필요한지 판단

- 실제 화면의 조작성·업무 적합성 등 사람의 판단, AI가 해결을 시도했지만 실제 사용자 환경에서만 가능한 필수 확인, 또는 사용자가 독립적으로 직접 체험을 요청한 경우에 4번 양식을 안내한다.
- 구현된 API·UI 핵심 동작 검사는 가능한 환경에서 AI가 직접 수행한다. 브라우저 자동화를 할 수 없으면 시도한 방법과 남은 범위를 기록한다. 단위 테스트·API 성공만으로 화면 조작까지 통과했다고 쓰거나, 확인하지 않은 기능을 사용자가 4번을 생략했다는 이유로 완료 처리하지 않는다.
- CLI만 있는 Phase에서 필요한 AI 검증을 마쳤다면 `PROGRESS.md`의 결과·선택 이유·한계를 읽도록 하고 다음 Phase의 3번 요청을 안내한다. 다음 Phase를 자동으로 시작하지 않는다.
- 사용자 직접 확인이 필요한 경우에는 **AI가 이미 확인한 것 / 사용자가 확인할 것 / 사람이 확인해야 하는 이유**를 먼저 구분한다. 자동 검사를 그대로 반복하는 목록을 필수 과제로 주지 않는다.

## 직접 확인이 필요한 경우에만 PROGRESS에 안내할 내용

- Phase·관련 기능·실제 테스트 판본(커밋 또는 변경 상태의 식별 근거).
- 실제 UI 주소/포트·유지할 프로세스·시작 화면/역할·준비 자료·적용 데이터/조건·기존 결과 상태.
- 사람이 확인할 정상 흐름·오류 후 조작·기대 결과. 사용자가 직접 CLI 확인을 요청했다면 그 요청 범위의 명령과 기대 결과도 안내하며 없는 URL을 만들지 않는다.

| 테스트 항목·직접 확인할 이유 | 시작 상태·입력 | 직접 할 조작 | 기대 결과 | 사용자 보고·확인 주체/판본 | 상태 |
| --- | --- | --- | --- | --- | --- |
| | | | | | 미확인 |

이 표는 직접 확인이 필요한 경우에만 `PROGRESS.md`에 작성한다. CLI Phase에 빈 사용자 보고란을 미리 만들지 않는다. 보고 전의 사용자 결과는 빈칸/미확인으로 두고 AI가 기대하는 결과를 사용자의 수행 결과로 미리 채우지 않는다. 관련 요구·검증 ID와 기술 근거는 해당 Phase에 연결해 사용자가 기술 표 전체를 읽어야 확인할 수 있게 만들지 않는다.

데이터 변경은 원본 복사본으로 한다. 데이터 적용·재계산·저장·내보내기의 사람 확인이 필요하면 담당 Phase의 검증 결과에서 실제 조작으로 확인할 부분만 안내한다. 화면 표시와 실제 저장·조회·출력의 데이터 판본·조건·내용을 대조하며 아직 없는 기능은 후속 통합 검증으로 남긴다.

## 보고를 받은 뒤 처리

1. 보고된 주체·판본·정상/실패/미확인·생략 범위만 `PROGRESS.md`에 기록한다. 일부 확인을 전체 통과로 확대하지 않는다.
2. 실패의 시작 상태·입력·조작·기대·실제를 확인하고, 승인된 범위에서 수정·AI 재검증을 수행해 해당 Phase에 근거를 기록한다.
3. 코드·자료·조건 변경의 영향 항목을 재확인 필요로 표시하고 이전 보고는 판본과 함께 보존한다. 사람의 재확인이 필요한 부분만 `PROGRESS.md`에 조작을 안내한다.
4. Phase 상태를 전체 `PLAN.md` 목차에 반영한다. 실패 수정 뒤 사람이 다시 확인할 항목이 있으면 그 조작과 결과 전달용 4번을 안내한다. 추가 직접 확인이 필요 없으면 다음 Phase의 3번 또는 5번 설명을 안내하고, 이미 반영한 같은 보고를 4번으로 다시 보내게 하지 않는다. 실제 대상 Phase와 할 일을 먼저 쓰고 해당 절·기본만/보충 포함 여부를 연결하며 새 프롬프트를 반복 생성하지 않는다.

Phase마다 사용자의 다음 요청을 기다린다. AI 확인·사용자 직접 확인·설명 제공·사용자 이해는 구분하되 사람의 미확인 자체를 모든 CLI Phase의 진행 장벽으로 만들지 않는다. 중간 종료를 위해 테스트 완료를 요구하거나 확인 결과를 만들어내지 않는다. AI 대리 확인을 사람의 직접 확인으로 바꾸지 않는다.
