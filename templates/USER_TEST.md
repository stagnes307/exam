# 필요한 사용자 확인과 보고 처리 — AI 지침

AI는 CLI/API·단위·백엔드 검사와 필요한 수정·재검증을 수행한다. 브라우저 자동화는 사용하지 않으며 UI 핵심 흐름은 사용자가 플랫폼 Browser에서 수동으로 확인한다.

**현재 조작 안내·미처리 보고는 PROGRESS, 반영한 보고 원문·상세 증거는 기존 담당 Phase**에 둔다. Phase가 아직 없으면 PLAN의 보관 절을 쓴다. 별도 사용자 테스트 문서나 보관 전용 Phase를 만들지 않는다. 지정 기록 문서는 재사용한다.

## 필요한 직접 확인만 준비

- UI의 정상 흐름·오류 후 상태·업무 적합성은 수동 확인에 배정한다. API 성공을 화면·실제 파일 생성/내용 확인으로 확대하지 않는다.
- UI가 없어도 업무 판단·사용자 환경에서만 가능한 필수 확인·요청한 체험은 해당 범위만 안내한다. 같은 판본에서 통과한 CLI의 사용자 반복을 필수로 만들지 않는다.
- UI는 서버를 `0.0.0.0`으로 실행하고 실제 PORT·경로·유지할 서버 터미널·시작 역할/자료/이전 결과 상태를 안내한다. 사용자는 플랫폼 Browser에서 그 PORT·경로로 연결한다.
- 필요한 사용자 CLI는 실행 위치·명령·입력·기대 결과를 안내한다. 원본 복사본에서 정상·오류 후 상태를 확인하고 저장·조회·내보내기가 있으면 판본·조건·내용을 대조한다.
- [PROGRESS 양식](../PROGRESS.template.md)에 대상·안내 기준 판본·빈 입력 공간을 AI가 준비한다. 사용자는 실제 결과·실패 조작·생략 항목만 적는다. 해시·ID·기술 문서 편집을 요구하지 않으며 기대값을 실제 결과로 미리 채우지 않는다.

직접 확인 대상이 없으면 빈 보고란을 만들지 않는다. 미처리 보고가 이미 있으면 먼저 보존·처리한다. 사용자 편집 중인 PLAN 답변·PROGRESS 보고를 덮어쓰지 않으며 저장 충돌은 양쪽 변경을 비교해 보존한다.

## 보고 원문을 안전하게 보관

1. 저장된 보고를 다시 읽고 실제 주체·판본·조건·범위와 정상/실패/미확인/생략을 구분한다. 안내한 판본을 실제 확인 판본으로 추정하지 않는다. 식별할 수 없는 항목은 미확인으로 남기고 판단에 꼭 필요한 정보만 확인한다.
2. AI가 프로젝트 안에서 유일한 보고 ID(예: `UT-001`)와 변하지 않는 제목/앵커를 부여한다. 기존 담당 Phase의 `사용자 보고 원문` 절에 원문을 그대로 보관한다. 여러 Phase에 걸친 보고는 담당 한 곳에 통째로 보관하고 다른 Phase는 같은 ID/원문을 연결한다. Phase가 없으면 PLAN에 둔 원본 위치를 이후에도 유지한다.
3. 주체·확인 판본/조건·적용 범위·현재 유효/재확인 필요와 해석은 원문 바깥에 기록한다. 원문의 글자·줄바꿈·공백·표·코드 블록을 바꾸지 않는다. 필요한 경우 원문 안의 코드 구분자보다 긴 바깥 구분자를 사용한다. 정정 보고는 새 ID로 추가해 이전 원문과 연결한다.
4. **복사본 저장 → 원문 동일성 대조 → PROGRESS 재읽기** 순서로 확인한다. 그동안 입력이 달라졌거나 보관 성공이 불확실하면 입력을 그대로 남긴다. 일치한 처리 블록만 PROGRESS에서 비우고 현재 결론·필요한 재확인과 원문 링크를 남긴다. 기존 보고의 재전달임이 확인된 경우 기존 ID를 연결하고 재보관·재검사하지 않는다. 문구가 같아도 새 실행·다른 판본·정정이면 별도 보고로 보존한다.
5. PLAN의 해당 Phase 근거 링크와 현재 PROGRESS가 보관 원문을 찾도록 맞춘다. PROGRESS에 모든 과거 보고의 목록을 누적하지 않는다. **보관 완료는 확인 통과가 아니다.** 실패·미확인의 현재 영향·해소 조건·다음 행동은 상단에 계속 남긴다.

## 보고 내용에 따른 처리 범위

**변경 없는 확인 보고:** 현재 PLAN 상태·해당 Phase의 완료 기준/근거와 새 보고를 대조한다. 기존에 읽은 요구의 맥락이 유효하고, 관련 코드·의존성·입력/조건이 기존 증거와 같으며, 새 실패·모호함·정정·요구 변경이 없는지 확인한다. 코드가 같다는 사실만으로 입력/환경도 같다고 보지 않는다. 이 조건이 맞으면 원문 보관·Phase의 해당 상태·PLAN 요약/링크·PROGRESS 결론과 다음 행동만 필요한 만큼 갱신한다. PRD·무관한 Phase·설명 전문을 다시 쓰거나 통과 검사를 반복하지 않는다. 과제 지정 기록 문서에 필요한 실제 변경은 반영한다.

**실패·수정·맥락 불확실:** 현재 PLAN·관련 PRD 요구/질문·해당 Phase와 [Phase 계획](PHASE_PLAN.md)의 검증 절차를 읽고 실제 상태를 대조한다. 새 세션이나 판본/조건을 확인할 수 없는 경우에도 이 경로를 쓴다. 실패의 시작 상태·입력·조작·기대/실제를 확인하고 승인된 범위에서 수정·허용된 AI 재검증을 수행한다. 알고리즘·목표·제약이 바뀌면 [문제풀이 지침](../PROBLEM_SOLVING.md)에 따라 해법·독립 검증·품질/비용 근거도 갱신한다.

변경 영향이 있는 과거 검증·사용자 확인은 재확인 필요로 표시한다. 보고 원문은 바꾸지 않고 새 판본에서 필요한 사람의 확인만 PROGRESS에 안내한다. 요구·완료 기준·의존 관계가 바뀌면 PRD·PLAN·영향받는 Phase를 함께 갱신한다. 증거를 재사용하면 범위·이유·재실행하지 않았음을 남긴다.

필수 실패·미실행이 남으면 검증 미완료다. 사람의 확인이 남으면 최소 절차와 4번, 불필요하면 다음 Phase의 3번 또는 5번을 안내하고 요청을 기다린다. 이미 반영한 보고를 다시 보내게 하지 않는다. 미완료와 독립적인 Phase는 의존 관계를 설명하고 사용자 요청 뒤 진행한다. 중간 종료는 테스트 완료를 요구하지 않는다.

세션 재개 시 PLAN의 실제 경로·승인·Phase 상태를 읽고, 현재 판단에 쓰는 보관 보고의 **원문과 판본/조건**을 해당 위치에서 확인한다. PROGRESS 요약이나 보고 ID만으로 사용자 확인·이해·제출 완료를 추정하지 않는다.
