# Phase 직접 기능 테스트

AI 검증은 활성 계획에 기록하고 사용자 직접 확인과 구분한다. Phase 종료 시 AI가 이 절차를 안내하며 사용자는 기능마다 승인을 반복하지 않고 Phase의 관련 흐름을 테스트한다. 사용자 보고 전에는 미확인이다.

## 실행 대상

- Phase·관련 요구 ID·프로젝트/PRD/계획 경로:
- 실제 테스트 판본(커밋 또는 변경 상태의 식별 근거):
- 실행 명령·작업 디렉터리·실제 접속 주소/포트:
- 유지해야 할 프로세스·시작 화면·역할·준비 자료:
- 초기 적용 데이터·조건·기존 결과의 상태:

## 조작과 실제 보고

| 테스트 ID·요구 ID | 시작 상태·입력 | 조작 순서 | 기대 결과·근거 | 사용자 보고·실제 결과 | 상태·확인 판본 |
| --- | --- | --- | --- | --- | --- |
| U1 · R1 | | | | 보고 전 | 미확인 |

현재 Phase의 정상 흐름과 중요한 오류·실패 후 상태를 확인한다. 데이터 변경은 원본 복사본으로 한다. 데이터 적용·재계산·저장·내보내기가 있으면 계획의 일관성 검증표를 직접 조작할 절차로 연결한다. 화면의 데이터/결과 표시와 실제 저장·조회·출력의 판본·조건·내용도 확인한다. 아직 없는 기능은 미확인 구간으로 구분한다.

## 수정과 재확인

| 실패 항목 | 수정·AI 재검증 근거(계획 링크) | 영향받는 사용자 항목 | 새 판본·사용자 재확인 결과 |
| --- | --- | --- | --- |
| | | | |

- 사용자 확인 완료/실패/미확인·생략의 실제 범위/판본:
- 변경 뒤 재확인할 항목·근거:
- 다음 Phase 또는 구현 설명에 대한 사용자 요청:

자료·조건·코드가 바뀌면 영향받은 항목을 재확인 필요로 표시하고 이전 결과도 판본과 함께 보존한다. 부분 확인을 전체 완료로 쓰지 않는다. 중간 종료 시 남은 항목은 미확인으로 유지하며 제출을 위해 확인 결과를 만들지 않는다.
