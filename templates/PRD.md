# 제품 요구사항(PRD)

AI 개발용 요구사항 문서다. 2단계에서 원문과 `PLAN.md`의 담당자 답변/검토를 근거로 작성한다. 기존 PRD·지정 문서를 재사용하고 전체 개발 순서는 `PLAN.md`, 구현·검증 상세는 `plans/`의 해당 Phase에 연결한다. 사용자가 확인할 범위·선택 사항은 `PROGRESS.md`에 쉽게 요약한다.

## 사용자와 범위

- 대상 사용자·역할·해결할 문제:
- 원문·PLAN의 확정된 답변에 근거한 목적·우선순위와 계획 제안:
- 사용자가 이미 전달한 선택·이유(있을 때만 기록하고 AI 제안과 구분, 재입력 요구 없음):
- 근거 문서·PLAN의 질문 ID/답변 원문·확정된 정정 링크(답변 원문은 복사하지 않음):
- 입력 자료·출력 규격·필수 제출물:
- 요구 형태: 함수/표준 입출력의 알고리즘 정답, 파일 처리, 또는 앱 기능 등 실제 원문의 산출물. 없는 UI·서버·DB는 계획하지 않음:
- 제외 범위·선택 기능·보류한 요구:

## 핵심 흐름과 완료 기준

| 흐름 ID·우선순위 | 사용자·시작 상태 | 입력·조작 | 관찰할 결과·완료 기준 |
| --- | --- | --- | --- |
| F1 | | | |

| 요구 ID | 원문 필수 조항의 위치·내용 / 확정된 정정·질문 ID | 관련 흐름 | 완료 기준·Phase/검증 ID 또는 비적용 근거 |
| --- | --- | --- | --- |
| R1 | | F1 | |

원문을 조항별로 다시 읽고 필수 기능·입출력·오류 처리·실행 조건·제출물을 위 표에 빠짐없이 연결한다. 여러 조항을 묶으면 각각의 원문 위치를 남긴다. **원문 필수 조항 → 요구 ID → 검증 ID** 방향으로 누락을 확인하며, 보류·미구현을 비적용으로 바꾸지 않는다. 비적용은 원문이나 권한이 확인된 정정 근거가 있을 때만 기록한다. 별도 추적 문서를 만들지 않는다.

- 자료별 업무 의미·중요한 가정·미확정과 그 의존 범위(답변 전체를 계획 전제로 삼지 않음):
- 데이터/조건 변경과 기존 결과의 유효성·실패/복구에 관한 실제 요구:

결과를 바꾸는 자료형·표현·단위·정밀도는 관련 요구에 정의 근거·허용/거절 예·내부 표현을 연결한다. 지정 표준이나 기계 판독 계약이 있으면 **해당 버전의 공식 정의를 읽거나 독립 참조 검증기로 대표값을 실제 대조**한다. 기억·언어의 타입 검사·제품과 같은 전처리로 대신하지 않으며, 파싱에서 원래 값의 정보가 사라지는지도 확인한다. 2단계에서는 기능 구현 없이 이 확인에 필요한 작은 참조 실험만 수행한다.

## 알고리즘 정의와 요구 수준 — 해당 과제만

계산·탐색·최적화 등 알고리즘의 정확성이 필요한 범위에 사용한다. [문제풀이 지침](../PROBLEM_SOLVING.md)을 읽고 아래에 실제 과제의 정의·선택·검증 계획을 반영한다. 원문이 요구한 문제를 먼저 정의하고 특정 업무나 구현 방법을 모든 과제에 강제하지 않는다.

| 원문·자료 근거 | 실제 입력 해석·결정할 값/고정값·허용 범위 | 제약·목적함수/방향·우선순위·조건 간 연결 | 해석을 가르는 작은 기대 사례·담당 Phase/검증 ID |
| --- | --- | --- | --- |
| | | | |

결과에 영향을 주는 항목만 원문과 실제 값으로 채운다. 탐색 편의를 위한 후보 제한·사전 고정은 원문 제약과 구분하고 유효성/품질에 미치는 영향을 남긴다. 작은 기대 사례는 원문·원시 입력에서 도출하며 상세 실행 결과와 실제 코드 대응은 담당 Phase에 연결한다. 특정 주제의 고정 항목이나 별도 모형 문서를 추가하지 않는다.

- 요구 수준: 정확한 결과/최적해, 정해진 근사 보장, 또는 허용된 휴리스틱과 그 근거:
- 입력 규모·값 범위·실행 시간/메모리 조건·전제와 선택 이유:
- 선택한 접근의 정확성 설명·독립 참조 검사·담당 Phase:
- 최적화가 목표일 때 기준 방법·개선 후보와 비교 조건·프로그램의 탐색 중단 조건:

### 하위 문제와 결합 계약 — 여러 핵심 풀이가 있을 때

| 하위 문제·역할 | 입력/고정값·결정할 값 | 출력 보장·다음 부분에 남길 상태/대안 | 공유 조건·결합 근거/되돌림 책임 | 원문 근거·담당 Phase/검증 |
| --- | --- | --- | --- | --- |
| | | | | |

작은 전체 풀이에서 반복·의존·공유 자원을 찾아 분해한다. 단일 해만 넘겨도 원래 해가 보존되는지 확인하고, 보존하지 못하면 필요한 결합 상태나 대안 전달을 계획한다. 하위 문제 각각의 정확성과 전체 합성의 정확성을 구별한다. 외부 탐색이 부르는 내부 판정의 정확성 수준, ID/순서/단위·정답 복원도 계약에 포함한다. 불필요하게 하위 문제나 Phase를 늘리지 않는다.

### 후보를 선택한 근거

| 실제 후보 | 이용하는 구조·필요 전제 | 정당화 핵심·공격한 반례/남은 공백 | 최대 규모의 전체 시간·메모리 근거 | 채택/기각 이유 |
| --- | --- | --- | --- | --- |
| | | | | |

상태 수×전이/연산 비용과 반복 호출·전처리·정답 복원을 실제 최대치에 대입한다. DP 상태/전이/기저·계산 순서, 탐욕 선택, 단조성, 가지치기 등 **채택한 방법에 해당하는 주장**을 문제풀이 지침의 반례 질문으로 검토한다. 기법 목록이나 고정 개수의 후보를 채우지 않는다. 작은 실험에서 반례를 못 찾았다는 것만으로 증명됐다고 쓰지 않는다.

요구 수준별 해법 선택·독립 검증·품질 개선 절차는 문제풀이 지침을 따른다. 위 정의와 비교 기준은 실제 과제에 맞게 작성하고, PLAN에서 담당 Phase의 구현·검증 작업으로 연결한다. 문서 링크만 남기거나 지침 전문을 복사하는 것으로 대신하지 않는다.

## 품질과 비교 기준

규칙 준수와 품질을 구분한다. 실제 과제에 맞는 지표를 선택하고 공식 기준이 없는 목표는 AI 제안과 실제 사용자 선택을 구분해 근거를 표시한다.

| 품질 지표 | 정의·단위·좋아지는 방향 | 선택 이유·근거 | 같은 입력으로 비교할 기준 방법·목표/허용 손실 |
| --- | --- | --- | --- |
| | | | |

- 규칙 준수의 독립 검사·핵심 기대값 근거:
- 비교할 입력·조건·규모와 실행 비용 측정 방법:
- 규모 확대·핵심 조건 변경 시 확인할 정확성/품질/성능:
- PLAN 목차·담당 Phase 상세 경로(실제 측정·차이·한계 기록):

특정 주제·알고리즘·Worker를 필수로 가정하지 않는다. 해당 없는 비교는 이유를 남긴다. 요구 변경은 근거와 영향받는 ID를 `PLAN.md`와 해당 Phase에 연결하고 이 문서에 반영한다. 완료 여부와 실행 로그를 중복 관리하지 않는다. 질문 전체의 답변을 기다리지 않고 미확정 의존 범위만 보류한다.
